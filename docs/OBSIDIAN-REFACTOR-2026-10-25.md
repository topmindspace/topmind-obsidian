# 4.20.0 整改记录：共享契约、持久会话与执行边界

本文只记录 4.20.0 的整改。其后版本已经发行。现行行为见 [ARCHITECTURE](../ARCHITECTURE.md) 与 [DESIGN](../DESIGN.md)。此前审查保留为[历史证据](OBSIDIAN-AUDIT-2026-10-25.md)。

## 结论与取舍

当前主要负担来自两端重复维护工具说明/参数/权限、视图混入会话调度、状态失败被当成空数据、对所有请求套用行动台账和续跑。单纯更换框架不能消除这些问题。本轮先把契约和数据边界收敛，删替代后的实现；编辑器与传输仍保留宿主适配。

适合精简的是重复声明、每次固定加载全部上下文、只读总结的任务续跑、历史方案与伪代码。需要加强的是正确对象、执行前冲突检查、真实工具结果、可恢复的待确认操作、状态损坏和取消语义。文件围栏、写闸、授权与证据仍有必要，不能依赖模型能力代替。

## 已完成整改

| 问题 | 实际变化与验证 |
|---|---|
| 两端工具参数容易漂移 | Kernel `agent-tool-catalog` 统一名称、双语说明、JSON schema 和读写分类；Desktop 绑定执行器，Obsidian 按宿主能力裁剪。根脚本逐字校验生成快照 |
| 重复权限与预算规则 | Kernel `agent-tool-policy`、`agent-policy` 统一记忆围栏、步数与写回文案；移除 Desktop 旧 memory-fence 与 Obsidian 内联副本 |
| 待确认队列全局缓存与失败丢项 | `workspace-state` / `pending-writes` 统一持久化；显式工作区、原子替换、损坏报错、失败留队列、已有普通文件 hash 冲突检测 |
| 删除确认执行错操作 | 队列显式区分 write/delete/archive；确认删除实际走 Kernel 删除，卡片明确“删除整个文件/确认删除” |
| View 内两套发送/重试状态机 | 新 ChatController 统一发送、重试、暂停、关闭、清空和持久化；chat-agent 从文件操作层拆出 |
| 历史与目标分开写且关闭即丢状态 | version 1 `chat-session.json` 保存消息、目标和运行；工具完成后 checkpoint，run id 隔离迟到结果。旧 history/goal 保留、只迁入一次 |
| 当前对象和未保存内容不可靠 | 固定发送时对象；重试/继续保留。写入前检查所有打开 Markdown 编辑器，确认卡片同样检查，避免失焦编辑器被覆盖 |
| 查询模型仍可能调用写工具 | 共享目录生成查询工具范围，执行时再次拒绝不可用工具。长总结在无写入意图时归只读，实际宿主模型调用从 4 次降为 2 次 |
| 后台取消只改 UI 状态 | Provider 调用前后检查取消与代际；迟到结果不进入消费者或建议合并 |
| 参数接收但无对应语义 | 待办按 idOrText、批量录入、幂等完成、正文更新保留截止日；scoped glob 先将绝对路径转相对路径再匹配；不再宣称宿主支持网页脚本渲染等未实现能力 |
| 聊天记忆卡片刷新/重载后消失 | 独立持久化聊天提案，刷新后台建议不丢卡；损坏存储明确可见 |
| 文档过量且含不实承诺 | ARCHITECTURE + DESIGN 从约 1300 行收敛为 223 行，删除历史伪代码，修正“同时编辑绝不冲突”“自动应用全部建议”，更新中英 README 和维护 runbook |

Desktop 工具构建器收敛为约 1156 行，约 600 行重复声明移入可复用契约。其余 Desktop UI/会话改动由同时进行的任务维护，本轮只接入共享契约、围栏和待确认操作，没有覆盖那部分重构。

公开工具 id 和旧参数保留兼容；用户旧历史文件不作为“冗余代码”删除。Pi 实验脚本保留作迁移依据，不作为已接入生产的能力宣传。Skills 的公开入口没有因为内部重构而改名，也未给每个宿主新增一套工作流规约。

## Pi 与生产架构

2026-10-25 再次核验，[官方 changelog](https://pi.dev/changelog) 最新条目为 1.4.0。官方 [SDK 文档](https://pi.dev/docs/latest/sdk) 说明 coding session 会发现资源、使用已存设置/凭证，并默认持久化会话；直接把完整 SDK 嵌进插件会与现有资源与状态所有权重叠。

本轮选择共享工具契约 + 独立 ChatController，为 Pi Agent Core 接入留出边界。生产仍是兼容 JSON 工具循环；没有增加未使用的 Pi 生产依赖。之前的 Core 宿主实验成功只证明基本可嵌入，不能代替服务商、流式消息和恢复的验收。

下一阶段原生运行时应通过明确的传输/事件 adapter 接入当前共享契约，替换文本调用解析与手工工具循环。迁移验收必须包含：原生 toolCall/toolResult、真实服务商协议、长上下文压缩、取消、暂停恢复、Kernel 写闸及错误证据。不要再平行新增第二份技能发现、身份配置和文件写入系统。

## 仍需完成的能力

| 优先级 | 边界或缺口 | 下一项可验收工作 |
|---|---|---|
| P1 | 通用整文件保存与跨进程并发没有完整事务保护；队列原子替换不提供多进程串行化 | 引入明确的版本/锁定策略并用两个真实进程验证冲突；不可承诺同时修改无冲突 |
| P1 | 当前会话 checkpoint 是目标与路径证据，并非完整原生工具消息/严格一次执行 | 随原生运行时落地持久消息与明确重放边界，验证中途关闭/崩溃后的重复副作用 |
| P1 | 聊天正式记忆写工具尚未对齐 Desktop；明确要求更新画像仍走确认卡 | 用正式语义工具传递本轮授权，区分用户指令与主动提案，补冲突/退役/恢复测试 |
| P1 | `requestUrl` 连接和已开始的同步 Kernel 操作不能保证即时中断；部分引擎内部派生写入不经过编辑器检查 | 收敛端到端取消协议和写入拦截，保持已完成修改的真实状态 |
| P1 | 未完成声明最低宿主 1.13+ 与真实模型的完整验收 | 增加受支持宿主测试矩阵与服务商集成/任务效果评测 |
| P2 | 暂无证据证明大库应默认引入向量库、完整 coding SDK 或另一套工作流引擎 | 先测检索命中率、工具成功率、完成率和上下文成本，再选基础设施 |

## 验证证据

- Obsidian：typecheck、Lint、234 项测试、build、ZIP 打包与 pack:verify 通过。
- 主仓最终 `npm run validate` 通过：692 项 Kernel/跨表面测试，151 项 UTR 测试，Desktop 1461 + 67 项测试，源码打包 12 项检查；共享契约、文档和安全扫描通过。
- Desktop 初次质量门在暂存插件版本 4.19.0 / 源码 4.20.0 不一致处失败；`desktop:pack:prepare` 更新暂存物后最终集成门通过。没有跳过该校验。
- 隔离实机：Obsidian 1.12.7 / Electron 39.8.3 / Node 22.22.1，通过 API 直接加载本地 4.20.0；使用独立 userData、临时 Vault 和本地 HTTP 模拟服务商。
- 实机通过 A→B 切换后仍绑定 A、总结只发 2 次请求、关闭重开恢复、卡片确认实际删除、待办录入/完成；页面异常为 0。
- 声明最低宿主仍为 1.13.0。上述直接加载不能证明正常市场安装或 1.13+ 设置页全部通过。未测试真实模型质量、正式 Desktop 安装包或跨平台 UI。

# 插件仓
npm ci
npm run typecheck
npm run lint
npm test
npm run build
npm run pack
npm run pack:verify

实机脚本是 [`scripts/smoke-obsidian.cjs`](../scripts/smoke-obsidian.cjs)，需本机已有 Obsidian 可执行文件与 Playwright。`--obsidian` 传真实绝对可执行路径；若 Playwright 不在项目依赖中，`--playwright` 显式提供已有模块解析目录。脚本使用随机本地调试端口，只结束自己启动的进程，截图与机器证据保留在其输出的临时 artifacts 目录。它不会打开日常 Vault 或读取真实模型密钥。
